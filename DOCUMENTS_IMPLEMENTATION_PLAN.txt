Step 1.2: Create Documents Table

  - owner_id (INT, FOREIGN KEY → users.user_id)
  - title (VARCHAR(255))
  - content (TEXT)
  - preview_text (VARCHAR(120))
  - language (VARCHAR(50), DEFAULT 'English')
  - created_at (TIMESTAMP DEFAULT CURRENT_TIMESTAMP)
  - updated_at (TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP)

- Verify documents table is created successfully

PHASE 2: CONTROLLERS (WITH DIRECT SQL)

Step 2.1: Create DocumentsController
- File: app/controllers/DocumentsController.php
- Functions (SQL inside):
  
  - createDocument($user_id, $title, $content)
    * INSERT query to documents table
    * Auto-generate preview_text (first 120 chars of content)
    * Set language to 'English' by default
    * Return document_id on success, false on failure
    
  - getDocumentById($document_id)
    * SELECT query to get single document
    * Verify document exists
    * Return document data as associative array
    * Return false if not found
    
  - getDocumentsByUser($user_id)
    * SELECT query to get all user's documents
    * ORDER BY updated_at DESC (newest first)
    * Return array of documents
    * Return empty array if no documents
    
  - updateDocument($document_id, $title, $content)
    * UPDATE query to modify document
    * Update preview_text (first 120 chars)
    * Update updated_at timestamp automatically
    * Verify document belongs to user (security check)
    * Return true on success, false on failure
    
  - deleteDocument($document_id, $user_id)
    * DELETE query (hard delete)
    * Verify document belongs to user (security check)
    * Return true on success, false on failure
    
  - searchDocuments($user_id, $query)
    * SELECT with LIKE for title/content search
    * Filter by owner_id for security
    * Search in both title and content fields
    * ORDER BY updated_at DESC
    * Return matching documents array

- Pattern: Like admin/user.php - functions with SQL inside
- Include database connection: require_once db_connect.php
- Use prepared statements for security
- Add error handling for database operations

PHASE 3: API ENDPOINTS/ROUTING

Step 3.1: Create Document API Endpoints
- File: app/controllers/documents_api.php
- Endpoints:
  
  - POST /documents/create
    * Start session
    * Get user_id from $_SESSION['user_id']
    * Get title, content from $_POST or JSON input
    * Validate inputs (title required, content optional)
    * Call DocumentsController::createDocument()
    * Return JSON: {"success": true, "document_id": id} or error
    
  - GET /documents/{id}
    * Get document_id from URL parameter or $_GET['id']
    * Call DocumentsController::getDocumentById()
    * Verify user owns document (security)
    * Return JSON: {"success": true, "document": {...}} or error
    
  - GET /documents
    * Start session
    * Get user_id from $_SESSION['user_id']
    * Call DocumentsController::getDocumentsByUser()
    * Return JSON: {"success": true, "documents": [...]}
    
  - PUT /documents/{id} or POST /documents/{id}/update
    * Start session
    * Get document_id from URL or $_POST
    * Get user_id from $_SESSION['user_id']
    * Get title, content from $_POST or JSON input
    * Call DocumentsController::updateDocument()
    * Return JSON: {"success": true} or error
    
  - DELETE /documents/{id}
    * Start session
    * Get document_id from URL or $_POST
    * Get user_id from $_SESSION['user_id']
    * Call DocumentsController::deleteDocument()
    * Return JSON: {"success": true} or error
    
  - GET /documents/search?q={query}
    * Start session
    * Get user_id from $_SESSION['user_id']
    * Get query from $_GET['q']
    * Call DocumentsController::searchDocuments()
    * Return JSON: {"success": true, "documents": [...]}

- All endpoints should:
  * Check if user is logged in (session exists)
  * Return proper JSON responses
  * Handle errors gracefully
  * Set proper HTTP status codes
